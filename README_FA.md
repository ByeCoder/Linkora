# لینکورا | Linkora — نسخهٔ ۲.۲

[English — مستندات اصلی گیت‌هاب](README.md) · **فارسی**

مستندات اصلی مخزن به انگلیسی‌اند. **در ربات، زبان از پیش به کاربر تحمیل نمی‌شود:** کاربر در اولین ورود ابتدا از میان هشت زبان انتخاب می‌کند؛ سپس منوی همان زبان نمایش داده و انتخابش ذخیره می‌شود. تغییر بعدی از `/language` ممکن است.

**شعار: جمع خودت رو پیدا کن 💚**

ربات کشف گروه و کانال با جست‌وجوی عمومی Waybien، رابط دوستانه در هشت زبان، پشتیبانی دوطرفه، پنل مدیریت، لاگ، آمار و ابزارهای جذب. نام نمایشی در اجرای اول تنظیم می‌شود. یوزرنیم باید در BotFather انتخاب شود؛ آزادبودن نامی مثل `LinkoraFindBot` بررسی یا تضمین نشده است.

این بسته سورس آمادهٔ تنظیم و اجراست. برای فعال‌شدن به توکن BotFather، شناسهٔ عددی مالک و سروری با دسترسی به تلگرام و Waybien نیاز دارید. هیچ توکن واقعی در بسته نیست و سرویس زنده‌ای مستقر نشده است.

## نصب سریع

روی Linux با Python 3.12، وارد پوشهٔ پروژه شوید:

```bash
python3 -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
python tools/setup.py --language fa
python -m bot
```

ابزار تنظیم، توکن را بدون نمایش می‌گیرد و برای شناسایی مالک راهنمایی می‌کند. اگر شناسهٔ خودتان را نمی‌دانید، برنامه پیام خصوصی ارسالی خودتان به ربات را نشان می‌دهد تا شناسه را تأیید کنید. فقط حساب خودتان را مالک بگذارید.

مستندات اصلی و رابط پیش‌فرض ابزار نصب به انگلیسی‌اند؛ آرگومان `--language fa` فقط متن‌های ابزار نصب را فارسی می‌کند. زبان خود ربات را هر کاربر جداگانه در اولین ورود انتخاب می‌کند.

روش دستی: `.env.example` را به `.env` کپی کنید، `BOT_TOKEN` و `OWNER_IDS` را مقدار بدهید. مالکان متعدد را با ویرگول جدا کنید. شناسه باید عددی باشد، نه یوزرنیم. بعد از اجرا، `/start` و `/panel` را در تلگرام بفرستید.

برای اجرای دائم با Docker:

```bash
docker compose up -d --build
docker compose logs -f --tail=100
```

دیتابیس در volume پایدار `bot_data` می‌ماند. `docker compose down` داده‌ها را نگه می‌دارد؛ `docker compose down -v` آن‌ها را حذف می‌کند. هم‌زمان فقط یک نمونه با یک توکن اجرا کنید. پورت ورودی و دامنه لازم نیست. اجرا از نوع long polling است. Windows از مسیر Docker پشتیبانی می‌شود؛ اجرای مستقیم از قفل `fcntl` لینوکس استفاده می‌کند.

اگر webhook از قبل فعال باشد، برنامه برای تغییرندادن سرویس قبلی اجرا نمی‌شود. پس از توقف سرویس قبلی، متد رسمی `deleteWebhook` را برای همین توکن اجرا کنید. برنامه خودش webhook یا updateهای قبلی را حذف نمی‌کند.

## راه‌اندازی پیشنهادی مدیر

۱. `/panel` ← مدیران: مدیران مورداعتماد را با شناسه اضافه کنید. فقط مالک امکان افزودن/حذف مدیر دارد. مدیران به اطلاعات کاربران، پشتیبان و پیام همگانی دسترسی دارند.

۲. دو گروه خصوصی برای «لاگ» و «پشتیبانی» بسازید و ربات را در آن‌ها ادمین کنید. با حساب مالک در گروه اول `/bindlog` و در گروه دوم `/bindsupport` بفرستید. دستورهای دارای `@bot_username` هم پشتیبانی می‌شوند. از پنل ← لاگ و پشتیبانی نیز می‌توان شناسهٔ گروه را تنظیم کرد؛ عدد ۰ اتصال را خاموش می‌کند. مالک باید قبلاً ربات را در خصوصی شروع کرده باشد.

۳. `/panel` ← عضویت اجباری: کانال را اضافه کنید. ربات باید ادمین کانال باشد. برای کانال عمومی `@channel_username` و برای خصوصی شناسه و دعوت را در یک خط بدهید:

```text
-1001234567890 https://t.me/+INVITE
```

تعلق لینک دعوت خصوصی به همان کانال را خودتان بررسی کنید. Bot API امکان اثبات تعلق یک لینک دلخواه را در اختیار این جریان نمی‌گذارد.

۴. حالت هدف کانال را انتخاب کنید و عدد هدف را تنظیم کنید؛ بخش بعد را ببینید. مقدار ۰ یعنی بدون پایان. بدون کانال تعریف‌شده، عضویت اجباری محدودیتی ایجاد نمی‌کند.

۵. از «جذب و هدف‌ها» امتیاز دعوت، جایزهٔ روزانه و در صورت نیاز حداقل دعوت برای بازشدن جست‌وجو را تنظیم کنید. شرط دعوت پیش‌فرض خاموش است.

۶. از «دکمه‌ها و ظاهر» متن‌ها، رنگ‌ها، ایموجی، ترتیب و چیدمان را شخصی‌سازی کنید. خوشامد هر زبان و پیشنهادهای منتخب هم از پنل تنظیم می‌شوند.

۷. با یک حساب معمولی تست کنید؛ مدیران از شرط عضویت و نگهداری معاف‌اند. کاربران عادی برای جست‌وجو، صفحه‌بندی، نتیجه‌ها و خروجی‌ها دوباره بررسی می‌شوند. خانه، زبان، پروفایل، دعوت، راهنما و پشتیبانی در دسترس می‌مانند تا کاربر در محدودیت گیر نکند.

## عضویت اجباری با هدف

| حالت | تعریف شمارش | رفتار در رسیدن به هدف |
| --- | --- | --- |
| تأیید یکتای کاربران ربات (`verified`) | تعداد شناسه‌های مختلف که ربات عضو بودنشان را بررسی کرده | شرط آن کانال برای درخواست‌های بعدی اعمال نمی‌شود |
| کل اعضای کانال (`members`) | تعداد اعضای فعلی کانال از `getChatMemberCount` تلگرام | شرط آن کانال خودکار خاموش می‌شود؛ روشن‌کردن دوباره با مدیر است |
| هدف ۰ | عضویت بدون سقف هدف | شرط ادامه دارد |

شمارش تأیید یکتا به معنی «عضو جذب‌شده توسط ربات» نیست؛ اعضای قبلی هم حساب می‌شوند و خروج بعدی از شمارندهٔ تجمعی کم نمی‌شود. حالت کل اعضا نیز منبع ورود اعضا را اثبات نمی‌کند. اگر تعداد واقعی کانال پس از رسیدن به هدف کاهش یابد، شرط خودکار دوباره روشن نمی‌شود.

حداقل دعوت برای بازشدن جست‌وجو مستقل از هدف کانال است. تأیید دعوت پیش از شرط تعداد دعوت انجام می‌شود تا بن‌بست ایجاد نشود. خطای بررسی عضویت، دسترسی را باز نمی‌کند. درخواست عضویت در انتظار تأیید، عضو محسوب نمی‌شود. حداکثر ۱۰ کانال تعریف می‌شود.

## امکانات کاربر و جذب

- جست‌وجوی واقعی Waybien، همهٔ پلتفرم‌های فعال فعلی سایت، صفحه‌بندی ۱۰تایی، فیلتر زبان/کشور/دسته/تعداد اعضا/قدمت، جزئیات و لینک ورود.
- دکمهٔ «بیشتر شبیه این» با جست‌وجوی دستهٔ همان نتیجه؛ پیشنهادهای منتخب مدیر؛ اشتراک نتیجه و لینک دعوت.
- علاقه‌مندی تا ۲۰۰ مورد، تاریخچهٔ ۲۰ جست‌وجوی آخر و خروجی CSV همان صفحه. علاقه‌مندی اطلاعات زمان ذخیره را نشان می‌دهد.
- تا ۵ جست‌وجوی ذخیره‌شده برای هر کاربر. اعلان نتیجهٔ تازه اختیاری و پیش‌فرض خاموش است. پس از روشن‌شدن، صفحهٔ اول حداکثر هر ۶ ساعت بررسی می‌شود؛ اولین بررسی فقط مبنا می‌سازد. تغییر شناسه‌های صفحهٔ اول ممکن است ناشی از تغییر رتبه باشد؛ ربات وعدهٔ پایش کل دیتابیس نمی‌دهد. اعلان فقط خبر می‌دهد؛ کلیک نتیجه دوباره شرط عضویت را بررسی می‌کند. خاموش‌کردن اعلان، موردِ هنوز ارسال‌نشده در صف را هم متوقف می‌کند.
- دعوت اختصاصی با deep link و پاداش یک‌باره. فقط کاربر جدید و عبور از شرط عضویت، دعوت را تأیید می‌کند. دعوت خود، کاربر قدیمی و تأیید دوباره امتیاز نمی‌گیرند. روش، حساب‌سازی یا هویت انسانی را به‌طور قطعی تشخیص نمی‌دهد.
- جایزهٔ روزانه با زنجیرهٔ حضور، امتیاز، جدول رتبه‌بندی با نمایش نام کاملاً اختیاری. امتیاز ارزش پولی ندارد. هر ۵۰ امتیاز، ۲۰ جست‌وجوی اضافه برای همان روز؛ حداکثر ۵ بار در روز.
- موضوعات محبوب از جست‌وجوهای همین ربات در ۷ روز اخیر به دست می‌آید؛ هر موضوع فقط پس از جست‌وجوی حداقل ۳ کاربر متفاوت نمایش داده می‌شود. عبارت شخصی را به‌عنوان جست‌وجو ننویسید؛ پشتیبانی مسیر جدا دارد.
- کمپین‌های مدیر با لینک ورودی اختصاصی و شمارش کاربران جدید هر کمپین؛ چند بار `/start` زدن، ورودی جدید محسوب نمی‌شود. ارجاع دعوت و کمپین دو نوع انتساب جدا هستند؛ یک پارامتر ورودی فقط یکی را ثبت می‌کند.
- پیام همگانی متنی برای همه یا یک زبان مشخص، با پیش‌نمایش، تأیید، صف پایدار و توقف. ترجمهٔ خودکار متن همگانی انجام نمی‌شود؛ مدیر متن مناسب همان زبان را می‌نویسد.

## زبان‌ها و متن‌های دوستانه

رابط کاربر، پیام‌های خطا، عضویت، پشتیبانی، دعوت، امتیاز و اعلان در **فارسی، انگلیسی، چینی ساده، هندی، عربی، عبری، اسپانیایی و فرانسوی** ارائه شده‌اند. منظور از درخواست «اسرائیلی»، زبان عبری (`he`) است. زبان در ابتدای ورود با انتخاب صریح کاربر تعیین می‌شود؛ تنظیم زبان تلگرام باعث ردشدن این مرحله نمی‌شود. انتخاب از `/language` قابل تغییر است.

پنل اپراتور به فارسی است. اطلاعات و گزینه‌های دریافتی از Waybien و متن آزاد نوشته‌شده توسط مدیر خودکار ترجمه نمی‌شوند. عنوان پیشنهاد منتخب می‌تواند به‌صورت JSON برای چند زبان تعریف شود. برچسب لینک دلخواه در ابتدا همان متن مدیر است و از طراحی می‌توان برای هر زبان برچسب جدا گذاشت.

نمونهٔ خوشامد پیش‌فرض: «سلام … 👋 به لینکورا خوش اومدی! اینجا آدم‌ها و جمع‌های هم‌علاقه‌ات رو پیدا کن ✨». برای تغییر: `/panel` ← خوشامد هر زبان ← `fa متن شما`. بازنشانی: `fa reset`.

## پشتیبانی دوطرفه

کاربر `/support` را می‌زند و متن، عکس، فایل، صدا، ویدئو یا استیکر می‌فرستد. تیکت شماره می‌گیرد و در گروه پشتیبانی یا، اگر گروه تنظیم نشده، به مالکان ربات می‌رسد. پیام‌های ارسال‌شده در این حالت تا `/cancel` یا برگشت به منو در همان گفتگو می‌مانند. فاصلهٔ پیام‌ها حداقل ۳ ثانیه و سقف روزانهٔ هر کاربر ۱۰۰ پیام است.

مدیر می‌تواند:

- در گروه پشتیبانی روی سربرگ یا نسخهٔ کپی‌شدهٔ پیام تیکت **ریپلای** کند؛ پاسخ به همان کاربر می‌رسد.
- از `/panel` ← تیکت‌ها، تیکت را باز کند و پاسخ بدهد یا ببندد.
- در خصوصی `/reply 123` بزند و پیام بعدی را برای تیکت ۱۲۳ بفرستد.
- روی نسخهٔ تیکت ارسال‌شده به چت خصوصی مدیر ریپلای کند.

فقط شناسه‌های مدیران ثبت‌شده یا مالک، پاسخ ارسال می‌کنند؛ عضویت عادی در گروه پشتیبانی اجازهٔ پاسخ‌دادن از طرف ربات نمی‌دهد. کاربر نیز فهرست آخرین تیکت‌های خودش و امکان بستن تیکت را دارد. پیام پس از بستن تیکت، تیکت تازه می‌سازد.

تاریخچهٔ پنل، آخرین ۵ پیام قابل کپی از تیکت را نمایش می‌دهد. دیتابیس متن و فایل خام همهٔ پیام‌ها را بایگانی نمی‌کند؛ برای بازنمایش، شناسهٔ پیام تلگرام نگه می‌دارد. حذف پیام اصلی یا محتوای محافظت‌شده ممکن است بازنمایش یا کپی را ناممکن کند. در خطای مبهم شبکه، پاسخ خودکار دوباره ارسال نمی‌شود.

## پروفایل کاملِ قابل‌دسترسی و لاگ

پنل کاربر، نام/نام خانوادگی، شناسه، نام کاربری، زبان تلگرام و ربات، وضعیت Premium، اولین و آخرین فعالیت، امتیاز، دعوت‌های تأییدشده، تعداد جست‌وجو و درخواست لینک، مسدودی و دسترس‌پذیری را نشان می‌دهد. هنگام مشاهده، بیو، تاریخ تولد، نام‌های کاربری فعال و کانال شخصی فقط اگر Bot API برگرداند اضافه می‌شوند. عکس نیز فقط در صورت دسترسی از تلگرام دریافت می‌شود. ۱۰ جست‌وجوی آخر در بخش مدیریت پروفایل دیده می‌شود.

شماره خودکار قابل دریافت نیست. کاربر می‌تواند از پروفایل، شمارهٔ خودش را با دکمهٔ مخصوص و اختیاری بفرستد؛ تماس متعلق به فرد دیگر ذخیره نمی‌شود. دکمهٔ حذف شماره هم وجود دارد. IP، ایمیل، مخاطبان و پیام‌های خصوصی دیگر کاربر قابل دریافت نیستند و در این پروژه ادعای دسترسی به آن‌ها وجود ندارد.

گروه لاگ مشخصات قابل‌دسترسی را برای ورود جدید، تغییر مشخصات، اشتراک/حذف شماره، دعوت تأییدشده، تیکت، پاسخ مدیر، خطای جست‌وجو، رسیدن کانال به هدف و عملیات مدیریت دریافت می‌کند. تصویر ورود جدید در صورت دسترسی فرستاده می‌شود. همهٔ جست‌وجوها به‌صورت پیام جدا به گروه لاگ ریخته نمی‌شوند؛ آخرین جست‌وجوها در پروفایل مدیر و دیتابیس هستند.

لاگ و تیکت صف پایدار دارند. وضعیت `pending/sent/failed/unknown/skipped` از منوی گروه‌ها دیده می‌شود. صف با نتیجهٔ مبهم خودکار تکرار نمی‌شود تا پیام تکراری ایجاد نکند؛ مدیر می‌تواند تیکت را از پنل باز کند. حذف شمارهٔ ذخیره‌شده، پیام قدیمیِ از قبل ارسال‌شده در گروه لاگ یا نسخهٔ پشتیبان را حذف نمی‌کند. گروه‌های دریافت‌کننده را خصوصی و محدود نگه دارید.

## مدیریت دکمه‌ها و ایموجی سفارشی

`/panel` ← دکمه‌ها و ظاهر. گزینهٔ `default` رنگ پیش‌فرض همهٔ دکمه‌های تولیدشده را تعیین می‌کند. دکمه‌های منوی اصلی، لینک ثبت، کنترل‌های کاربر، خانوادهٔ دکمه‌های نتیجه، لینک‌های دلخواه و دکمه‌های مدیریت در فهرست تنظیمات هستند.

- **متن هر زبان:** `fa بیا بگردیم 🔎`؛ برای پاک‌کردن برچسب اختصاصی همان زبان: `fa reset`.
- **رنگ:** `primary` آبی، `success` سبز، `danger` قرمز، `default` پیش‌فرض برنامهٔ تلگرام. رنگ دلخواه RGB، گرادیان و CSS در دکمهٔ معمولی Bot API وجود ندارد.
- **ایموجی سفارشی:** یک پیام شامل custom emoji بفرستید تا شناسه استخراج شود، یا `custom_emoji_id` عددی بدهید. عدد `0` آن را حذف می‌کند. شرایط Telegram Premium مالک یا نام کاربری واجد شرایط Fragment طبق Bot API لازم است. داشتن Premium توسط کاربر نهایی به‌تنهایی این مجوز را برای ربات فراهم نمی‌کند. در ردشدن تزئینات با خطای مشخص API، کیبورد بدون رنگ و ایموجی دوباره ارسال می‌شود.
- **ترتیب:** ۰ تا ۱۰۰۰؛ عدد کمتر در منوی اصلی بالاتر است.
- **نمایش/پنهان:** برای ورودی‌های منوی اصلی و لینک‌های دلخواه اثر دارد. دکمه‌های فرایندی مثل هر ردیف نتیجه بر اساس داده تولید می‌شوند؛ پنهان‌کردن منو، فرمان `/support` و `/start` را از بین نمی‌برد.
- **چیدمان:** یک یا دو ستون.
- **لینک دلخواه:** حداکثر ۱۰ مورد، عنوان و لینک `https` در دو خط؛ بعداً برچسب هر زبان، ترتیب و رنگ را تنظیم کنید.

تغییر برچسب خانوادهٔ دکمه‌های پویا می‌تواند عنوان اختصاصی ردیف نتیجه را جایگزین کند؛ معمولاً متن آن‌ها را پیش‌فرض نگه دارید و فقط رنگ/آیکن را تغییر دهید. ظاهر روی کلاینت‌های قدیمی ممکن است ساده نمایش داده شود.

## آمار دقیق روزانه، هفتگی، ماهانه و کلی

همهٔ شمارش‌ها از دیتابیس همین ربات‌اند. پیش‌فرض زمان `Asia/Tehran` است؛ روز از نیمه‌شب، هفته از شنبه، ماه **شمسی** از روز اول ماه جاری، و کل از آغاز ثبت داده‌ها. پنل ← آمار ← تغییر شمسی/میلادی، تقویم ماهانه را عوض می‌کند. پایان همهٔ بازه‌ها لحظهٔ درخواست گزارش است؛ زمان‌های خام دیتابیس Unix UTC هستند.

هر بازه شامل کاربر جدید، فعال یکتا، درخواست جست‌وجو، پاسخ موفق و خطا، درخواست لینک، رد عضویت، دعوت تأییدشده، تیکت جدید و پاسخ موفق مدیر است. کاربر جدید، نخستین پیام خصوصی ثبت‌شده است؛ حتی اگر هنوز شرط عضویت را نگذراند. فعال یکتا یعنی شناسه‌های متفاوت دارای تعامل. پاسخ موفق شامل پاسخ خالی معتبر، cache و صفحه‌بندی است. توقف فرایند بین درخواست و دریافت نتیجه ممکن است باعث شود جمع موفق/خطا با درخواست‌ها برابر نباشد.

ورودی جدید کمپین هم در هر بازه شمرده می‌شود. از آمار ← «آمار روزبه‌روز»، هفت روز اخیر را جداگانه ببینید؛ «CSV سی روز» خروجی ۳۰ ردیفی با هر دو تاریخ شمسی و میلادی و همهٔ شاخص‌ها می‌دهد. رویداد دقیقاً روی نیمه‌شب فقط در روز جدید حساب می‌شود. فعال یکتای کل، جمع سادهٔ فعال‌های روزانه نیست؛ یک نفر ممکن است در چند روز فعال باشد.

درخواست لینک به معنی کلیک واقعی روی URL یا عضویت واقعی در گروه نتیجه نیست؛ Bot API این دو را گزارش نمی‌کند. تعداد اعضای گروه‌های جست‌وجوشده را Waybien اعلام می‌کند و ربات مستقلاً تأییدشان نمی‌کند. خروجی CSV آمار و کاربران و پشتیبان SQLite از پنل قابل دریافت است.

## ارتقا از نسخهٔ قبلی

۱. ربات قبلی را متوقف کنید و پشتیبان بگیرید.
۲. سورس را جایگزین و `pip install -r requirements.txt` یا `docker compose up -d --build` را اجرا کنید.
۳. همان `.env` و دیتابیس/volume قبلی را نگه دارید. ستون‌ها و جدول‌های جدید خودکار اضافه می‌شوند؛ کاربران، تاریخچه، علاقه‌مندی‌ها و کانال‌های قبلی حفظ می‌شوند.
۴. ماهانه به‌طور پیش‌فرض شمسی است؛ برای میلادی از پنل انتخاب کنید. هدف کانال‌های قبلی ۰ و بدون پایان است.
۵. گروه‌ها و هدف‌ها را تنظیم کنید. کاربر قبلی به‌صورت خودکار دعوت جدید محسوب نمی‌شود.

برای بازیابی، فرایند را کامل متوقف و دیتابیس را با پشتیبان جایگزین کنید؛ `.env` جدا نگه داشته می‌شود. فایل‌های قدیمی `-wal` و `-shm` فقط پس از توقف کامل و کنارگذاشتن دیتابیس قبلی از مسیر دیتابیس جدید خارج شوند.

## مرز اتصال Waybien

جست‌وجو از دادهٔ عمومی Next.js Flight صفحهٔ `/en/search` و فهرست فیلترها از مسیرهای عمومی `dashboard.waybien.com` خوانده می‌شود. `page` در این سایت offset است: ۰، ۱۰، ۲۰ و… . این رابط عمومی، قرارداد API تضمین‌شده نیست؛ تغییر ساختار یا محدودیت دسترسی سایت ممکن است به‌روزرسانی بخواهد. پاسخ نامعتبر، «نتیجهٔ خالی» جا زده نمی‌شود. تعداد کل، عدد اعلام‌شدهٔ سایت است و دسترسی به کل دیتابیس خصوصی را تضمین نمی‌کند.

**ورود به حساب Waybien، ثبت/ویرایش/حذف گروه در حساب، رأی‌دادن، گزارش به سایت، تبلیغات، پرداخت و درآمد داخل تلگرام پیاده نشده‌اند.** لینک مسیرهای سایت در دسترس است. علاقه‌مندی، امتیاز و آمار برای همین ربات‌اند. اتصال داخل ربات برای قابلیت‌های خصوصی به API و احراز هویت مجاز صاحب سرویس نیاز دارد. محدودیت‌های سایت دور زده نمی‌شوند.

## بررسی و عیب‌یابی

```bash
pip install -r requirements-dev.txt
python -m pytest -q
python tools/check_site.py python
python tools/check_site.py python --platform telegram --offset 10
```

نتیجهٔ آزمون‌ها در `VALIDATION_FA.md` و بررسی نمونه‌های مشابه در `RESEARCH_FA.md` آمده است.

- خطای 401 تلگرام: توکن نادرست/باطل.
- خطای 409: اجرای هم‌زمان یا تداخل webhook.
- عضویت همیشه رد می‌شود: شناسهٔ کانال، ادمین‌بودن ربات و حالت هدف را بررسی کنید.
- تیکت به گروه نمی‌رسد: گروه متصل، وضعیت صف، دسترسی ادمین و کپی‌پذیری پیام را بررسی کنید. تیکت از پنل نیز قابل مشاهده است.
- اگر گروه لاگ/پشتیبانی به سوپرگروه ارتقا یابد، شناسهٔ مقصد و موارد هنوز ارسال‌نشدهٔ صف با پیام رسمی مهاجرت تلگرام به‌روز می‌شوند. پیام‌های قدیمی را در صورت نیاز از پنل تیکت دوباره باز کنید؛ یکسان‌بودن شناسهٔ پیام‌های تاریخی فرض نمی‌شود.
- اگر اعلانِ پاسخ به یک کلیک به‌دلیل تأخیر منقضی شود، خودِ عمل دکمه همچنان پس از کنترل مالک دکمه و مجوزها بررسی می‌شود. دیگر خطاهای API پنهان نمی‌شوند.
- 403/429 یا پاسخ نامعتبر سایت: محدودیت/تغییر سایت؛ ابزار بررسی و دکمهٔ سلامت اتصال را اجرا کنید.
- سرور باید به `api.telegram.org` و Waybien دسترسی داشته باشد. httpx متغیرهای استاندارد پراکسی محیط را می‌خواند؛ پراکسی داخل کد قرار داده نشده است.
- Docker هنگام خروج فرایند آن را مجدداً اجرا می‌کند؛ unhealthy بودن به‌تنهایی باعث restart Docker نمی‌شود.

معماری برای یک فرایند است. برای چند نمونه و ترافیک سنگین باید صف و دیتابیس سرویس‌محور جایگزین شوند. ارسال شبکه‌ای و تراکنش دیتابیس مشترک نیستند؛ exactly-once در تلگرام تضمین نمی‌شود. رویدادها برای آمار کل نگه داشته می‌شوند؛ پاک‌کردن تاریخچه، رویدادهای آماری و لاگ‌های قبلی را حذف نمی‌کند. توکن در فایل‌های خروجی و لاگ معمول برنامه چاپ نمی‌شود.
